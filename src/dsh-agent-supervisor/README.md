# dsh-agent-supervisor

## 0.1.3-dsh021rc3.3：避免状态读取竞态误报“已中止”

修复了异步读取日志投影与随后读取 live Agent 状态之间的竞态：日志仍显示当前轮未结束、Agent 已在正常收尾变为空闲时，旧版会误报 stopped。现在在异步读取后同步重采样实时投影与运行状态；只有明确的终止事件或暂停锁才显示“已中止”。无结束证据的状态间隙显示“同步中”，并显示状态说明与时间，不再当作终止。

发送 send_message 的送达回执不代表子任务完成，也不会取消任务；实际用户停止、父级联动、错误、暂停和正常完成的语义保持。当前版本不能追溯未记录的历史界面帧，因此只能将历史案例判为与该缺陷一致；回归测试可确定复现旧版错误和验证修复。

## 0.1.3-dsh021rc3.2：手动恢复 goal 与联动停止一致

修复原生“恢复目标”刚把 goal 恢复为 active，旧任务树停止锁便取消其消息并使 goal 立即回到 paused 的冲突。只有后端已提交的 `resume`、精确的当前 goal 版本、原生已 armed 状态，以及无模型发起者的当前运行根会话才解除该根的旧锁。自动 goal 消息、普通目标更新、旧事件回放、子代理和模型工具不能借此解除人工停止。

处理过的同一轮用户停止，其迟到 `turn/end` 不再重复上锁。后续新停止仍正常生效；其它根和单独暂停的分支不受影响。不会清空收件箱、重置次数、改任务结果或恢复不明进程。手动恢复由原生 goal 服务校验并提交，权限和次数门仍以宿主为准。

回归证据覆盖旧版失败、修复通过、真实 rc.3 的目标服务/驱动/Agent，以及实际浏览器的“恢复目标”按钮。测试只调用离线适配器，不运行业务模型。没有把“本轮完成”解释为计划全部完成；等待父消息的可续聊子代理仍需准确的新消息才能继续。

本修复适用 rc.3；包保留原 rc.2 声明，但未对 rc.2 扩展本轮恢复能力作验收。缺少原生发起者、根归属或 goal 校验接口时不自动解锁，仍需通过显式的 supervisor 恢复入口。

DSH 0.2.0-rc.2 的独立合并插件：右侧子代理列表、原生子代理对话入口、真实计划进度和协作式级联停止。不是之前撤回的子代理侧栏或 Better Sidebar，也不修改 Office 插件。

## 界面

- 输入框上方显示当前会话下级代理的运行数/总数。点击打开右侧「子代理」标签；也可从右侧「开始 → 子代理任务」打开。0.1.3 按用户要求删除插件在主会话标题栏增加的入口，原生子智能体菜单保留。
- 列表包含直属和下级代理，运行中排在前面，可搜索、仅看运行中，按 80 项分页。每次最多读取 2,000 项，超限明确显示数量下限；不把缺失记录当成零。
- 运行中绿色点渐闪，正常结束绿色点常亮，终止错误红点，中止/等待/未知灰点，受阻/正在停止琥珀色点。遵守系统减少动画偏好。运行状态沿用原生 Agent 的状态，可能包含工具或审批等待，不表示持续产生模型费用。
- 外层显示子代理自身首条任务说明、最近可见回复与计划进度，不显示推理内容，不拿父会话继承的任务/计划冒充子任务。文字均以纯文本渲染。
- 0.1.2 在代理名称下显示模型 ID、供应商及可用的推理强度；支持按这些字段搜索。优先读取自身最后一个解析后的 `request/header` / `request/context`，即使已完成或当前不驻留也能显示历史实际路由。没有自身请求时只显示自身运行配置或明确的自身 descriptor 配置，并标「配置」；其余显示「模型未知」。不将父会话继承的请求头作为自身模型，不把 subagent provider（例如 spawn/fork）误认为 AI 供应商。模型切换后跟随新请求更新，不控制或更改模型选择。
- 0.1.3 模型读取同时从原生 Session 事件或只读 SessionQuery 观察回放自身日志，不依赖新增投影是否已经加入旧缓存；驻留记录增量缓存，冷记录不启动代理、不打开写句柄。客户端检查宿主 API 标识，旧宿主未加载更新时显示「宿主待更新」，不直接误报模型未知。若出现这一提示，需正常重开 DSH 完整载入宿主。
- Plan 只使用子代理自己的 `todo/write` 记录，百分比为完成项数 / 总项数；进行中不预先计完成。无计划显示「未提交计划」，上一轮计划明确标「上轮」。正常结束不会强行将不完整计划改成 100%；「已完成」表示原生当前轮次正常结束，不等同于所有业务目标已验收。
- 点击子代理标题，在同一右侧栏打开官方原生对话标签，主会话保持不动，列表标签保留。使用精确的直属父子地址，复用官方对话、轨迹和输入框；一次性代理保持只读，可续聊代理遵守官方可用性与权限判断。收起或关闭查看标签不取消任务、不删除记录。

## 联动停止

- 默认开启「联动停止」。用户点击原生停止，插件通过本轮原生取消信号停止该代理及全部下级；正常完成、网络重试和非用户取消不触发这一联动。
- 0.1.1 按用户要求移除插件自行添加的所有停止按钮，包括输入框上方、列表工具栏及条目按钮。统一使用主会话原有蓝色停止按钮联动下级，不添加第二套停止入口，不改原生按钮和原生子代理输入框。
- 只遍历带原生 `subagent` 来源和准确父子链的代理。普通独立会话、独立分支及其他主会话不受影响。不按名称、工作区路径或时间猜测归属。
- 任务树暂停期间，迟到的新代理及后台回传不能自行开启新的模型步骤。接受的原生队列消息保留，不通过清空收件箱实现停止。新的人类输入到暂停根会话会解除这一暂停；播放图标只解除暂停，不发送消息、不自动启动任务。下级界面会提示来自上级的暂停，明确解除操作作用于对应上级任务树。
- 对插件载入前已经运行的轮次，另有用户中止的 `turn/end` 事件兜底；尚未结束的旧轮次无法保证立即联动。正常重启后，新轮次均可在请求前绑定信号。主会话自然完成或变为空闲不等同于用户点击停止，不触发级联取消。
- 「正在停止」不当作已停止。已经完成或失败的历史状态保留，不因父级停止全部改成中止。暂停状态存于 `$DSH_HOME/dsh-agent-supervisor/state.json`，只保存选项与暂停 ID/时间/令牌，不复制聊天内容、密钥、附件或产物。状态不可读时关闭自动联动并显示错误；状态保存失败也会显示。

停止是原生协作式取消，不是全局进程终止器，不强杀外部软件，也不撤销已经执行的文件或业务操作。外部提供者没有可核验的本地运行状态时可能显示未知。插件卸载不会恢复已经中止的模型请求，也不删除会话、结果或状态文件。

## 实现与验证

宿主使用公开的 Agent 生命周期、Session 投影和查询服务；HTTP 沿用宿主鉴权并限制同源、JSON 控制及请求大小。客户端使用官方 slots 和原生 `subagentchat` 资源，不改 app.asar，不替换整个会话控制器，不绕过子代理权限。

- `node --test test/*.test.js`：模型、归属、停止、暂停恢复、HTTP 与状态文件回归。
- 本轮隔离浏览器验证了排序、摘要、真实计划、状态点、原生地址、主草稿保留、过滤、离线状态、停止/恢复以及 1280/420/320px 布局。
- 本轮用实际官方 Cordis、Session 投影及 AgentLoop 创建临时代理，验证三级取消、其他根不受影响、后台通知不唤醒、原生待处理消息保留及明确用户输入恢复，模型调用数为零。测试使用临时 DSH_HOME，不触碰业务会话。
- 官方原生侧栏资源提供者实际接受本插件地址，引用释放和一次性代理只读规则已经验证。
