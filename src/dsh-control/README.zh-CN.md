# DSH Control 1.12.0

## 父子会话独占交接（1.12.0）

主会话可以将自己已观察、已登录的原标签交给真实直接子代理。交接只改变浏览器标签归属和原生颜色组，不创建标签、不导航、不复制 Cookie 或令牌，因此保留当前页面的 sessionStorage、内存登录状态、草稿和滚动位置。交出后主会话立即失去该标签访问权，旧观察全部作废；子代理必须重新 observe，继续按自己的会话权限操作。

模型流程：先用 DSH 创建子代理并得到其实际 ID，再调用 `control_browser`：

```json
{"action":"handoff","tabId":"原标签ID","observationId":"主会话当前观察ID","targetSessionId":"直接子代理ID"}
```

返回 tabId、loanId、接收会话与 requiresObservation。告诉子代理观察这个 tabId，不要重新 open。子代理完成后用 `{action:"return-tab",tabId,loanId}` 归还；主会话也可用 `{action:"reclaim-tab",tabId,loanId}` 收回。旧 loanId 不能用于之后的新交接，借用标签不能继续转交或被子代理 close-tab/close-browser 关闭。

GUI：电脑操控 → 父子会话标签交接 → 刷新交接对象 → 选择本会话标签与直接子代理 → 交给子代理。借用中会显示“收回标签”。有正在执行的操控时拒绝交接，不强行中断；交接不唤醒代理、不解除暂停、不改变权限或跳过 Auto Review。专用浏览器重启恢复后保留交接关系；用户自有浏览器重新连接仍需显式选择。

## 一次调用执行多步（1.11.0）

模型在一次 control_browser 或 control_desktop 调用中使用 action:sequence 与 steps，可提交 1..8 个同一页面/窗口内的已观察控件动作，无需先 prepare-batch 再等待模型调用 batch。权限审查覆盖整个明确序列，本机逐步核验并执行，最后一次返回 completed 与 postObservation。不会在每一步之间重新请求主模型。

```json
{"action":"sequence","observationId":"本次观察编号","mode":"mouse","steps":[
  {"action":"type","elementId":"e10","text":"需要发送的内容"},
  {"action":"click","elementId":"e11"}
]}
```

浏览器后续点击目标可以最初处于禁用状态，例如输入后才启用的发送按钮；插件只等待这个原有节点启用，最多 5 秒，不修改禁用属性，不换一个按钮。出现替换、语义变化、权限变化或人工停止时，立即停止剩余步骤，返回完成记录，不能重放已完成输入。只支持已观察的 click/type/hover/scroll（桌面也支持登记的 perform），不执行任意脚本、未知页面操作、导航或嵌套序列。需要新页面信息时仍应先观察。

## 重启 DSH 保留浏览器（1.11.0）

默认专用 Chrome/Edge 以独立进程运行，DSH 退出或重启仅断开控制连接，保留窗口、标签和页面内尚未发送的内容。下一次同会话的浏览器操作会自动连接原进程、恢复原生标签组与标签 ID；旧观察、输入授权和审批缓存不会恢复，必须重新观察。仅恢复保存的同一页面目标与同一原生组，不开放其他会话或未交接的页面。

本地恢复文件只保存浏览器连接标识、会话归属和标签组信息，不保存网页 URL、表单内容或密码。输入框草稿由仍然运行的浏览器页面保留。DSH 异常退出时，页面内操作提示会在失去心跳后自行隐藏。此行为适用于由新版本启动的专用浏览器；浏览器自身退出或电脑重启不保证页面内存草稿可恢复。

高级配置 preserveBrowserOnExit 默认为 true，设为 false 可恢复随 DSH 结束的旧行为。显式 close-browser 仍关闭当前会话所属标签，GUI 断开控制则保留页面但取消自动接管归属。用户自己的浏览器保持原来的显式交接流程。

## 操控空闲与任务停止（1.10.1）

15 分钟未继续电脑/浏览器操作，只收起操控提示、关闭人工输入监听并清除本会话可复用授权，不取消 DSH 会话、不设置 CONTROL_STOPPED。模型可以继续读取文件、分析或使用其他工具；之后需要操作时会重新显示提示，并按当前会话权限重新核验。正在执行的操控和待审批请求不会被当作空闲。

人工点击停止、Esc 或接管仍会立即停止并锁定本轮操控，需要新的人类消息或用户恢复。日志把空闲记为 released / idle-timeout，不再伪装成用户停止。

## 浏览器布局自适应（1.10.0）

只指定 elementId 的点击、输入、悬停、滚动会在执行前重新核验同一 DOM 节点并计算当前位置。窗口移动、响应式尺寸变化、CSS 缩放、页面滚动和普通重排不再仅因控件矩形变化而阻断。操作仍需目标在当前视口中可见；移出视口需先滚动或重新观察。输入内容、控件语义、文档与标签归属的核验保留。

显式传入 x/y、拖拽端点、曲线路径或笔画时仍使用严格几何校验，不把旧图像坐标自动解释为新位置。希望适应布局变化时只传 elementId。返回的 targetGeometry 包含观察时与执行时矩形、实际 CSS 坐标及 relocated 标记。浏览器原生窗口位置与 CSS 像素分离，截图继续返回裁剪/缩放变换；系统分辨率不需要按物理像素硬编码。

虚拟鼠标移到目标后会再次核验；悬停引起一次重排时会重新定位，最多尝试三次鼠标移动，尚未发送点击或文字。持续移动、被遮挡、节点替换或名称/链接变化会停止。浏览器命名控件批量操作也可以适应重排，每一步仍按原节点和语义核验，不增加步骤、不重放已完成操作；桌面批量几何校验不变。

## 长上下文导致观察超时（1.9.2）

截图坐标的基础有效期仍为 60 秒。模型处理长上下文或等待审批可能超过这个时间，所以浏览器 click/hover/scroll/type 对同一已观察控件增加了实时重新核验：默认 10 分钟内可核验原标签、原文档、原 DOM 节点、名称/链接/类型、位置和遮挡，再按原有权限执行。输入框内容与控件状态也必须与观察时一致；私有比较值仅保存在内存，不出现在工具结果或日志中。每次执行前都重新检查，不会刷新旧观察时间或把一个控件的核验变成整页授权。

坐标操作只有能绑定到该次观察中同一控件时才使用此机制。无法定位的旧 Canvas/空白区域坐标、密码框、真正导航/替换/遮挡/内容变化、显式坐标所依赖的几何改变，或者超过 10 分钟上限的观察，仍需新观察。只按控件定位时可重新计算当前位置。桌面和原图 map-point 不延长有效期。支持审批前与审批后重新核验，任一阶段目标语义改变都不执行，不自动重放操作。

成功结果的 observationCheck.revalidated 表示本次重新核验通过，仍应优先使用返回的 postObservation。高级配置 browserRevalidationMaxAgeMs 默认 600000，可设 60000..1800000；这不是关闭校验，也不跳过 Auto Review。

## 浏览器输入修复（1.9.1）

原生文本光标闪烁通常只重绘像素，不改变 DOM；网页自定义光标、焦点样式等修改 class/style 时会增加页面版本。旧版坐标输入只比较页面版本，容易因此误报 UI_CHANGED；不传 elementId 和坐标时又把缺少目标误报为 OUT_OF_VIEWPORT。

现在 type 可以指定已观察输入框的 elementId、输入框内的 x/y，或省略两者以使用本次观察中已聚焦的输入框。坐标会先绑定到已观察的具体 DOM 控件，再按相同节点身份、名称、类型、位置、遮挡和可编辑状态核验；无关 DOM 更新不阻止输入。点击后使用 postObservation，再发 type 即可。省略目标不会任意寻找当前焦点：如果焦点已从观察中的框移走，返回 FOCUS_CHANGED，不会向别的框写入。

输入框的名称优先来自 aria-label、aria-labelledby、HTML label 等稳定信息；富文本内容与光标不作为控件名称。支持 textarea、contenteditable 和 plaintext-only 编辑框。鼠标聚焦后、全选替换后再次检查目标与焦点，焦点被点击或键盘事件抢走时停止发送文字。控件替换、遮挡、只读和禁用仍会被拒绝；显式坐标下的移动继续拒绝，不绕过权限或审批。

## 非视觉主模型与独立视觉插槽

在会话输入区打开“电脑操控”，将“视觉辅助”设为“开启，独立视觉模型看图”，填写“视觉供应商 ID”和“视觉模型 ID”，保存设置。供应商沿用 DSH 已配置的地址和密钥，不需要在插件里重复填写。这里必须选支持图片输入的模型，不会自动沿用非视觉主模型，也与审批模型互相独立。设置按会话保存，旧会话默认关闭；关闭后保留已填路线供再次启用。

开启后，桌面与浏览器的 screen/screenshot/observe/wait 以及输入后的 postObservation 会附带 `vision` 文字描述、可见文本、候选目标和坐标，返回给主模型的工具内容只有文字，无图片块或 base64。无障碍树仍保留，能使用 elementId 时优先使用真实控件。look 会取得新截图，并可通过 question 提问，例如：

```json
{"action":"look","question":"找到登录按钮，描述当前位置和遮挡情况"}
```

桌面 look 可指定 windowId；省略时查看全屏。浏览器 look 可指定本会话 tabId。候选 point 已从截图相对坐标换算为绝对屏幕坐标或 viewport CSS 坐标，支持裁剪、缩放和负坐标显示器；必须配合同一个 observationId 使用。桌面视觉坐标先 prepare 检查命中，再原样执行 perform；浏览器点击仍经过原有观察、归属及目标校验。视觉结果不是授权，不会调用操作工具、自动执行或覆盖 Auto Review。

截图发送到用户选定的视觉供应商，每次查看与输入后检查会调用该模型并按供应商计费。只发送本次截图、有限的无障碍名称及看图问题，不复制完整对话或审批上下文。整个分析期间继续显示当前操控提示并支持人工接管。已知不支持图片的模型在发送前拒绝；调用失败、输出格式错误、超时或读取期间观察失效时，返回 vision.ok:false，不提供可执行候选，不自动重试。已经完成的操作会保留 performed:true，禁止因后续看图失败而重放操作。

`visionTimeoutMs` 默认 30000，可在插件配置中设为 1000..120000；视觉调用不会放宽 observationMaxAgeMs。视觉定位准确率取决于所选模型，本地自动验收使用真实 DSH 图片服务及确定性像素识别适配器，没有冒充远端视觉模型的 OCR/语义能力测试。

本版修复远程/录屏看不到悬浮提示：WDA_EXCLUDEFROMCAPTURE 也会让远程观看者失去提示。全部原生提示使用 WDA_NONE；普通桌面捕获可见，插件自截图只在读取像素时暂时隐藏自身提示并恢复。

独立的 Windows 桌面与 Chromium 浏览器操控插件，适配官方 DSH Desktop 0.2.0-rc.2。支持真实鼠标、UIA 后台输入、浏览器虚拟鼠标、持续顶部提示、人工接管和按会话审批。不是 Codex 私有组件的复制。

## 安装与设置

解压 ZIP，运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1`。安装器使用 DSH 自带 Node/pnpm，备份配置，保存版本源码，启用本插件并停用旧 dsh-click / tool-browseruse 入口，保留旧文件和首次安装前回滚点。也可安装 `dsh-control-1.12.0.tgz` 并启用 bundle。已有其它操控插件时可使用 -KeepOldPlugins 仅升级本插件。刷新 DSH 页面后，点击输入区“电脑操控”打开 GUI；可选择审批和视觉模型、清除同类授权、停止/恢复和测试悬浮提示。

浏览器默认“本会话此站点浏览授权”：首次审批理由会明确站点与浏览范围，合法子域的链接导航、搜索、滚动、切换标签可复用；不同会话、站点、协议或端口仍独立。发布、购买、上传和无法确认性质的写操作仍单独审批，原生 Auto Review 仍逐次执行。GUI 可改为“每次操作审批”。停止、清除授权、权限/设置变化及插件重启清除站点授权。

权限跟随每个 DSH 会话。原生 Auto Review 保留优先级，拒绝不会被插件审批覆盖。完全权限选项不能突破会话授权边界。人工审批可允许一次或记住本会话相同目标和参数；修改目标、参数、权限或设置需要重新审批。停止与插件重启清除授权。配置 provider/model 为空时跟随会话模型，两个字段必须一起填写。

设置 API 使用当前页面的随机能力令牌、同源校验和已打开主会话检查。模型工具没有更改审批配置的入口。模型请勿加载旧放行技能、修改权限、执行启动命令或读取快捷方式文件来替代明确要求的 GUI 操作。

## 持续提示与接管

从第一次查看屏幕开始，原生浮层在该屏幕上侧置顶，显示查看、审查、审批、鼠标、后台、浏览器、分析和受阻等待状态；输入步骤之间仍显示。显示等待绘制与置顶回执，运行期间检查窗口存活，停止请求用递增代次拒绝延迟显示。聊天区不放状态条。

Esc、停止按钮或真实鼠标点击/键盘输入结束干预；路径输入也检查人工移动鼠标。停止后不能由模型自行重试或恢复，需要新的人工消息或用户点击“恢复操控”。浏览器协同暂停会保留当前窗口和标签，先中止加载再隐藏提示，不以关闭用户页中断任务。普通观察期间移动鼠标可以查看，点击/按键才接管。GUI 的“测试悬浮提示”显示 10 秒，不截图、不取得输入控制权、不改变权限。

浏览器操作不显示桌面悬浮；状态、阶段、虚拟指针与停止按钮只在所属页面内显示，浏览器物理输入监听不占用系统鼠标。浏览器页面同时有边框、阶段提示、虚拟指针和停止按钮。浏览器鼠标不移动操作系统指针。原生浮层与输入控制权分别管理：输入互斥锁用于执行动作，持续提示覆盖整个干预过程。

## 基本 GUI 流程

`screen` 看当前屏幕 → `locate query:真实名称` → 原样执行返回的 `perform`（只复制 requestId）→ 需要等待时调用 `wait` → 使用新观察继续。桌面被挡时先定位并点击“显示桌面”，再定位应用。应用内部按钮要在 `locate` 中传该 windowId；省略时只查桌面和任务栏。locate/prepare 读取 UIA 用于定位，返回的方案实际用 SendInput 鼠标，不是后台点击。

有确定的截图坐标时，`prepare + observationId + windowId + x/y` 做只读命中检查，返回登记的鼠标方案。方案按会话、进程身份、控件身份、几何、动作和点击次数核验。签名事实用于审查，不授予权限。旧 click 签名方案仍兼容；优先用 perform 避免复制复杂证据。

observe 后直接使用新 observationId，不混用旧 screen 编号。UI_CHANGED、ELEMENT_CHANGED、遮挡或过期时重新观察；检查已执行效果，不自动重放。成功结果的 postObservation 用于下一步。只报告截图和窗口已经证实的成功。

## 有限批量操作

先观察同一窗口/标签页，再调用 prepare-batch 登记 1..8 个已观察命名控件的步骤；只允许 click/type/hover/scroll，桌面也可使用命名控件的 perform。不能嵌套批量、跨窗口、猜坐标、导航、启动应用或执行按键。后台动作必须有对应模式，浏览器只读输入框等会在登记阶段拒绝。

```json
{"action":"prepare-batch","steps":[
  {"action":"type","mode":"uia","observationId":"本次观察编号","elementId":"e3","text":"第一栏"},
  {"action":"type","mode":"uia","observationId":"本次观察编号","elementId":"e5","text":"第二栏"}
]}
```

随后原样执行返回的 `{action:"batch",requestId:...}`。编号描述已登记动作与目标；主机保存不可修改的完整步骤。审批审查整个明确组合，每一步重新观察并核验进程/页面、控件身份、名称、位置、可用性和会话权限。实际副作用按批准步骤逐一执行，没有跳过原生 Auto Review。

失败返回已完成步骤、failedStep、mayHavePartialEffect 和 replayAllowed:false。一个批量计划开始尝试执行后即不可重放；观察实际结果，为剩余步骤重新登记。它不是事务回滚，也不是同意整个对话。单批文字总数最多 40000 字符，单个 type 保持 20000 字符限制。

## 条件等待

桌面和浏览器均支持 wait；waitMs 范围 200..10000 毫秒，默认 2000。条件：window（窗口/页面标题前缀）、active-window（当前前台窗口/选中可见页面）、element（控件出现）、enabled（出现且可用）、focused（控件获得焦点）、text（文字匹配）。桌面控件条件可指定 windowId，浏览器可指定 tabId；query 使用实际名称。

```json
{"action":"wait","condition":"enabled","query":"启动","windowId":12345,"waitMs":5000}
```

完成或超时都返回新观察与截图、wait.matched/timedOut/elapsedMs。窗口出现不等同于按钮已就绪。超时不自动重复启动、不读取进程；根据当前界面决定后续步骤。等待可由人工接管中断，不取得输入控制权。

## UIA 缓存与界面变化

桌面读取使用 .NET UIA CacheRequest 批量取控件属性和模式，遍历缓存子节点，减少逐属性 COM 调用；按名称定位只取匹配节点详情。仍有元素数量、深度和时间预算，truncated/警告会明确返回。缓存只用于读取，执行前使用当前进程、控件指纹、位置和遮挡核验。

对已观察窗口订阅 UIA 结构与相关属性变化，记录焦点变化；浏览器使用 DOM/input/scroll/resize 监听。真实变化使旧观察失效。浏览器输入会再核验同一个 DOM 句柄的身份、名称、链接、类型、位置和可用性；无关动画更新不阻止不变的已观察控件。导航和切换仍绑定同一标签/文档/当前 URL，不要求无关 DOM 静止。延迟属性通知核对实际当前属性和快照，避免误伤已经包含该变化的新观察。窗口关闭/移动、控件移除、导航或页面文档代次变化也会在执行前拒绝旧目标。提供商不支持事件时 changeMonitoring:false，仍执行即时核验；并不把监听当作唯一边界。

## 区域截图与坐标映射

screen/screenshot 支持 region:{x,y,width,height} 和 maxWidth:160..4096。桌面 region 使用绝对屏幕坐标（可为负的虚拟桌面坐标）；浏览器 region 使用 viewport CSS 坐标。区域必须完整位于观察范围，越界拒绝，不自动裁剪到其他区域。maxWidth 只缩小图片，不改变窗口/浏览器布局或输入几何。

返回 captureRect、图片实际宽高和 imageTransform：originX/originY、scaleX/scaleY、imageWidth/imageHeight。`map-point` 把本会话图片像素回映成屏幕/CSS 坐标；桌面 prepare 可直接加 coordinateSpace:image 使用该截图的 x/y。

```json
{"action":"screenshot","windowId":12345,"region":{"x":300,"y":250,"width":800,"height":400},"maxWidth":400}
```

不能把缩小图片坐标直接用于鼠标输入。原生提示默认允许远程桌面和录屏捕获，不再使用全局捕获排除。只有插件自己截图时短暂隐藏自己的浮层，完成后恢复；浏览器截图短暂隐藏自己的页面指示，原生顶部提示与接管仍有效。浏览器密度与页面滚动包含在映射中，额外测试了模拟 2x 密度。

## 曲线路径与多笔画

桌面和浏览器的 drag 可提供 path:[{x,y},...]；strokes 提供多笔画 [[{x,y},...],...]。默认 mouse；不支持后台 UIA 绘画。每笔 2..256 点，1..32 笔，总计最多 1024 点；durationMs 100..10000 是时长目标，检查与投递有额外开销。路径和 endX/endY 不能同时提供。

```json
{"action":"strokes","mode":"mouse","observationId":"新观察编号","elementId":"绘制控件编号","strokes":[
  [{"x":400,"y":300},{"x":430,"y":240},{"x":460,"y":300}],
  [{"x":415,"y":275},{"x":445,"y":275}]
],"durationMs":1000}
```

全部路径点先检查边界；逐段投递期间继续核验窗口、绘制控件和遮挡。指定 elementId 时范围限于该绘制控件。每笔之间松开鼠标；取消、超时或中断也释放持有的输入。支持 S 形路径和按笔画画字，不是文字识别、自动排字、压力笔/触控笔模拟。直线 endX/endY 接口保持兼容。

## 浏览器与平台范围

支持已安装 Chrome/Edge/Chromium。专用浏览器用一个独立于日常用户目录的 shared-groups 资料目录，在同一窗口中建立每会话不同颜色的原生标签组；资料目录共享，因此组间 Cookie/登录状态共享，这是原生组的限制。工具标签注册、观察编号、popup 归属与授权按会话隔离；不能枚举或操作其他组，手工移出组的标签会被拒绝。只关闭当前组不会影响别组。原生组由附带的最小 MV3 扩展与私有 CDP 连接维护，无网页消息入口，不向模型开放脚本/扩展权限。

GUI 的“浏览器协同”可连接用户已有 Chrome/Edge。Chrome 144+ 可在 chrome://inspect/#remote-debugging 开启调试并确认浏览器连接许可；auto 读取本机调试端点，也可填本机 http/ws 地址，禁止远程主机与凭据地址。此连接不重启用户浏览器。连接后 GUI 列出未归属用户标签，用户点击“移入本会话组”才允许模型看到/操作该页，未选私有页不进入工具列表。交接标识限当前会话与短期有效期，其他会话不能使用。断开、暂停和取消保留用户标签与窗口；最后断开只关闭调试连接并卸载自己的扩展，不退出用户 Chrome。默认浏览器用虚拟鼠标，mode:dom 可后台 click/fill，返回模式区分合成事件。URL 仅 http/https/about:blank，禁止包含凭据。结构化元素主要来自主页面，iframe 可使用已观察截图的 CSS 坐标。Firefox/IAccessible2 接入、OCR、浏览器扩展桥接和任意页面脚本执行未加入公开工具。

桌面需要交互式 Windows 和 .NET Framework。不能跨越 UAC/管理员、安全桌面与系统保护。PrintWindow 对 GPU 窗口可能黑屏，此时用可见 screen；区域和映射不绕过系统保护。实机验证使用单显示器，负坐标由单元验证，未声称多显示器混合 DPI 已实测。实际审批供应商可用性与批准结果取决于其配置，性能也包含模型往返。
